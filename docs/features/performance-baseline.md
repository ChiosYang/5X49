状态：Done

基准覆盖用户打开片库、搜索、影片详情、观影日记和设置的等待时间，也覆盖普通 API 读写、后台任务与维护操作。使用生产版 Next.js、真实 FastAPI、SQLite、Chromium 和合成媒体。数据库和媒体写入都在测试运行器创建的临时目录中。

## 复跑

在 `frontend/` 执行 `npm run test:perf`。依赖安装和 Chromium 设置同 [真实 API 浏览器测试](../real-api-e2e.md)。默认依次扫描 12 部和 1,000 部各自带 NFO、封面及有效短视频的影片。可用 `npm run test:perf -- 48` 校验脚本。自定义规模的结果要与相同规模、相同工作负载版本比较。

每次运行输出独立的 `frontend/e2e-artifacts/performance-<UTC>/report.json`。完整运行标记为 `complete: true`。原始样本保留毫秒数。报告同时记录版本、机器规格、浏览器以及测量脚本的摘要。

每次扫描的业务结果单独保存在 `tiers[].scans`，包括任务终态、结束时可查询的影片数及轮询状态接口时的 HTTP 错误计数。大片库首次扫描失败且入库数为零时，测试会用同一份 NFO 每批准备 20 部影片，再测原目录复扫和下游功能。失败耗时单列，只有成功扫描才会进入耗时指标。

## 计时口径

- 单请求 API 使用回环 HTTP，在 Node 客户端计时至响应体读取和 JSON 解析结束。普通读取排除一次预热，记录 25 次。个人状态、观影记录、手工元数据与语言设置记录 20 次真实写入。
- 并发测试使用同一组片库分页、关键字搜索、详情和关系图请求。1 和 8 个客户端分别闭环完成 80 个请求，记录每个请求的延迟，以及整个批次的每秒请求数。
- 浏览器使用英文界面及 1440×900 和 390×900 两种视口。每个页面重新打开一个标签页，浏览器 HTTP 缓存因网络拦截而关闭，服务进程保持运行。记录主文档 TTFB、FCP 和指定内容出现后再经过两个动画帧的时间。另测筛选抽屉、从片库打开详情、返回筛选结果、提交搜索四个操作。每项排除一次预热，采集 20 次。
- 页面就绪使用具体元素作标记。例如片库使用第一张影片卡片，详情使用关系图标题，日记使用观影记录链接。标记须通过 Playwright 可见性检查；它可以位于折叠线下方。FCP 由 Chromium 的 Paint Timing API 提供。
- 首次扫描指空片库导入，复扫使用同一批文件。分别报告入队回执及提交到任务成功的端到端耗时。后台任务每 250 ms 检查一次完成状态。备份包含 ZIP 生成、下载，以及现有离线恢复工具的校验、恢复和应用启动探针。
- 20 个及以上样本报告中位数和最近秩 P95。低频维护操作保留样本数、中位数和最大值。RSS 是阶段结束时观察到的进程驻留内存，CPU 秒数是对应进程的累计值。
- TMDB 使用固定测试响应，后端阻止外网连接。视频检查使用固定负载观察值和真实 FFmpeg。样本结果仅用于同条件比较。

## 数据与边界

两档片库都由种子 549 生成。每个影片目录有 NFO、封面、背景图和可解码的短视频。按 TMDB 编号每五部预置一条日记及评分，每十部标为收藏。读写负载按相同次序运行，异步操作从客户端提交开始计时。首次扫描使用空片库，第二档复用同一服务进程。浏览器从本机访问生产版 Next.js，再由前端请求 FastAPI。API 单项和混合并发直接请求 FastAPI。

AI 谱系分析测一次固定模型输出的生成、持久化和一次相同输入复用。语义检索固定使用 12 份索引文档，覆盖合成决策、嵌入、重排和快照重读。身份裁决与视频解码使用单独的小夹具，备份恢复使用带已知记录的归档，并验证恢复后的应用能启动。第三方真实推理、互联网或 NAS 传输速度、实体手机 CPU 性能和长时间稳定性仍待独立测量。

片库首页请求最多返回 40 部，因此两档的首页响应分别含 12 和 40 部影片。外部评分覆盖刷新状态读取，线上评分源、海报下载和 API 密钥连接测试的往返耗时仍待在线环境测量。1 和 8 客户端的结果用于观察本机混合读取随并发的变化。它们不能推算极限并发或生产环境 SLA。

### 单目录扫描结果

- 12 部首次导入成功，耗时 4.62 秒，结束时可查询 12 部影片。
- 12 部原目录复扫成功，耗时 3.46 秒，结束时可查询 12 部影片。
- 1,000 部首次导入失败，耗时 163.24 秒，结束时可查询 0 部影片。
- 1,000 部原目录复扫失败，耗时 108.35 秒，结束时可查询 1,000 部影片。

为继续测量同一批 1,000 部影片，基准在空库中按每批 20 部解析原 NFO，并使用实际影片与结构化元数据写入逻辑建库。准备数据耗时 176.55 秒，独立记录在 `fixtureLoad`。后续复扫仍走完整目录的正常 API。

独立复现使用全新 SQLite 数据库和同一生成种子。1,000 部单目录扫描在持久化阶段失败，219.21 秒后可查询影片数为 0，捕获的 SQLite 异常为 `OperationalError: database is locked`。本次测试定位到了失败阶段，具体持锁连接尚待排查。
